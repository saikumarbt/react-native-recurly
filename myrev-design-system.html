01

Overview

What myrev is, who it's for, and the rules the design obeys.

Product

Track subscriptions, recurring bills, and upcoming payments in one place.

Local-first: data lives on the phone. No bank login.

Guest-first: fully usable with no account. Sign-in is optional, for backup later.

One base currency. No conversion.

Reminders fire before renewals and before free trials end.

Business rules the UI must honour

Free tracks up to 5 active subscriptions. Paused and cancelled don't count.

Pro is recurring only. No lifetime.

Pro v1 has no AI. Value is unlimited subs, backup, custom reminders, widgets, cheaper-plan finder, cancel guidance.

Trials are excluded from spend until they convert.

Base currency locks once any subscription exists.

Out of scope v1: AI plan / Ask myrev / forecasts (v2), calendar tab (cut), multi-currency.

Copy voice. Write like a sharp friend. Short lines, concrete numbers, plain labels. A button says what it does, then the toast confirms it: "Cancel" then "Cancelled". The assistant speaks first person only when it's the assistant: "I found $312 you could cut."

Sort & filter (within the status groups)

Sort chips — Renewal · Price · Name; each toggles ascending/descending (tap the active chip to flip, ↑/↓ shown). Applies inside each group, not across them (Active still lists above Cancelled). Renewal picks soonest, Price priciest, Name A–Z by default.

Group fallbacks under "Renewal" (no upcoming date): Cancelled → cancellation date, most-recent first; Paused → Name. Price/Name sort every group uniformly.

Adaptive category filter — ≤6 categories render as wrapping chips (no horizontal scroll — a sideways affordance isn't obvious); >6 collapse to a "Filter · N" pill → multi-select sheet (search + per-category counts + Clear all). Threshold INLINE_CATEGORY_LIMIT=6.

Keyboard dismisses on scroll (keyboardDismissMode="on-drag") on the list + filter sheet. Adding a sub resets search + category filter so the user lands on the full collapsed list and sees what they just added.

11

User flows

Happy path plus the edges that must not break. Guest-first throughout; auth only where noted.

Onboarding → reveal → trial

Intro → (goal) → currency → pick (accordion) → confirm prices → analyzing → reveal → trial offer.

Decline → dashboard. Accept → lands on the dashboard, then the paywall presents over it (dismissing drops onto the dashboard, not back into onboarding).

Skip at any step → dashboard with 0 subs (empty state teaches add).

Add subscription

FAB (any tab) → /add sheet → brand → price + cycle → Add → toast.

Duplicate active name → nudge to rename or add anyway.

Free at 5 active → cap wall instead of add; existing data untouched.

Price ≤ 0 → inline validation, blocks add.

Cancel / pause

Detail → Cancel → celebration + savings + share card.

Savings milestone crossed → MilestoneCelebration → optional store-review prompt (rate-limited).

Pause → excluded from spend + reminders; resume restores.

Settings actions

Currency: freely set while no subs exist; locked once any sub exists (guarded reset only).

Reminders toggle → permission prompt on enable → reschedule.

Export → CSV/JSON → OS share sheet. Restore purchases → RevenueCat restore + feedback.

Delete account → confirm → Clerk delete (if signed in) + full local wipe (subs + all kv prefs) + RevenueCat logout/reset + dev-override clear → onboarding. ("Clear all data" is subs-only.)

Pro purchase & trial (RevenueCat)

Any Pro CTA (cap wall · onboarding reveal · Found teaser · Insights · Settings) → /paywall.

Login before checkout: guest → sign-up (returnTo) → returns to paywall & auto-resumes the trial once. Ties the RC entitlement to the Clerk id (cross-device Pro).

Buy → isPro flips via the CustomerInfo listener → paywall dismisses → Pro unlocks. Cancel → silent; error → alert. Double-charge guard: synchronous re-entry lock + skip-if-already-Pro (+ store/RC dedupe).

Trial state surfaced in Settings ("converts on/renews on/cancels on/payment issue") so a charge is never a surprise. Needs a native dev build — Expo Go can't run purchases.

Pro → Free downgrade (over-cap)

Grace is the store's own (RC keeps the entitlement active during billing-retry / until a voluntary cancel's period-end) → a Home winback banner (WinbackBanner): "Update payment" (billing issue) / "Reactivate" (pending cancel) → store's manage-subscriptions page. A locked sub nearing renewal also gets one upgrade-framed locked_renewal push.

Truly lapsed & >5 active → /reconcile: pick which 5 stay active (default = soonest-renewal / highest-spend); the rest are locked (paused + view-only, "Reactivate with Pro", no reminders). Nothing deleted.

Resubscribe → DowngradeWatcher auto-unlocks all locked subs. Reactivate a single locked sub → cap-gated (free if under 5, else paywall).

Analytics consent (GDPR)

EEA/UK first launch (post-onboarding) → one-time opt-in prompt; analytics stays OFF until accepted.

Rest of world → opt-out default (Settings toggle). Decision persisted; never re-prompts.

Navigation

Structure

Root Stack (expo-router) → (tabs) Tabs + modal routes.

Tabs keep their own state/scroll; switching tabs preserves position.

Drill-ins keep the menu: subscription detail is a nested stack inside the Subscriptions tab; Found is a hidden tab (href:null). Both show the tab bar + a BackButton (Back pops to the list/prior screen).

Modals stay menu-less (focused overlays, frosted backdrop): /add, cap wall, cancel sheet, pickers, /paywall, /analytics-consent.

/reconcile is a forced fullScreenModal (gesture-disabled, no dismiss) — the only exits are "keep 5" or "Reactivate Pro". Driven by DowngradeWatcher when a lapsed user is over the cap.

Guarded back everywhere (canGoBack() ? back() : replace('/')) so a modal reached via replace can't throw GO_BACK.

Onboarding + auth are full-screen pushes, not tabs.

Platform & links

Android hardware back + iOS swipe-back both dismiss sheets/modals and pop the stack.

Deep link scheme myrev://; renewal reminder → /subscriptions/[id] (buffered until navigator mounts).

Auth is optional; no redirect wall. Guest reaches everything except backup/Pro.

17 · 18

Responsive & platform

Devices

Small / standard / large phones; portrait only (orientation: "portrait").

Layout is fluid: the tab bar's 4 buttons + centre FAB are each flex-1 across (width − 40); no fixed widths, so it adapts from 320px up.

Safe areas via useSafeAreaInsets; tab bar clears the bottom inset; content uses pb-32 clearance.

Notch / Dynamic Island respected; brand names truncate; large a11y text reflows without clipping.

iPad (phone-first, centred column)

Not a stretched phone layout: the whole app is capped to a centred column at TABLET_MAX_WIDTH = 600 (app/_layout.tsx) — full-width on phones, centred on iPad with the theme colour bleeding to the edges (intentional, not a black letterbox).

RN <Modal> sheets render in their own full-device window, so the root cap can't reach them; .modal-container mirrors it with max-w-[600px] self-center (keep the two 600s in sync).

Submission: supportsTablet:true + portrait-only requires ios.requireFullScreen:true — without it App Store validation fails (Apple wants all-orientation support for Split View, or an explicit opt-out).

v2 (deferred, demand-gated): a true iPad master-detail (list + detail side by side, wider Insights) if iPad becomes a real audience — not launch-blocking.

iOS vs Android (intentional)

Date picker: inline calendar vs native dialog.

Share & export via the native share sheet (expo-sharing).

Blur strength 24 (iOS) / 50 (Android) since Android blur is weaker.

Back: swipe (iOS) vs hardware button (Android); haptics via expo-haptics.
